# Contributing

Start with a concrete decision that the existing catalog does not cover well. Explain its boundary against neighboring profiles and include a realistic case.

For an adaptation, pin the source repository, commit and file, retain its full applicable license notice, record the original file hash, and explain the changes. Check the relevant method rather than accepting an upstream checklist unconditionally.

Each diagnostic item should include its applicability condition, the evidence to check, its effect on the recommendation and a resolvable source reference. Include a scenario with an expected judgment and an unacceptable conclusion.

Update catalog metadata when changing a profile. Increment the version for changed configuration. Run `pnpm test`, then review the method against representative cases. State the limits of the evaluation and keep unverified performance claims out of the profile.

Professional validation remains a separate recorded status. Keep secrets, private conversations, production datasets and generated runtime captures outside pull requests.
